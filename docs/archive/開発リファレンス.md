## A. デザインシステム詳細

> 元ソース: `デザイン.md`

### デザイン原則

| 原則 | 説明 |
|------|------|
| **Bold（大胆）** | 太い線、はっきりしたコントラスト、迷いのない表現 |
| **Playful（遊び心）** | アニメーションで「触りたくなる」体験を作る |
| **Clear（明快）** | 余計な装飾を排除し、情報を直接伝える |
| **Unified（統一）** | どの画面でも同じルールに従う |

### カラーパレット

```
背景:     #FFFFFF（純白）
テキスト: #000000（純黒）
```

| 名前 | 用途 | カラーコード |
|------|------|-------------|
| **Mono** | デフォルト、ホーム | `#000000` |
| **楽天テーマ** | 楽天主義 Language View | `#ff6b35`（オレンジ） |
| **燕市テーマ** | 燕市 Language View | `#10b981`（エメラルドグリーン） |
| **Pattern View** | Pattern Viewのアクセント | `#2563eb`（青） |

> ⚠️ アクセントカラーはシャドウとラベル背景のみに使用。テキストや背景全体には使わない。

### タイポグラフィ

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont,
             'Segoe UI', Roboto, sans-serif;
```

| 用途 | サイズ | ウェイト | スタイル |
|------|--------|----------|----------|
| 見出し（カードタイトル） | 1.5rem | 900 (Black) | UPPERCASE |
| 本文 | 0.875rem | 400 | 通常 |
| ラベル | 0.625rem | 800 | UPPERCASE, letter-spacing: 0.1em |
| ナビリンク | 0.75rem | 800 | UPPERCASE |

### ボーダーとシャドウ

```css
/* ボーダー */
border: 3px solid #000;  /* カード */
border: 2px solid #000;  /* 内部要素、ボタン */

/* ハードシャドウ（blur禁止） */
通常時:  box-shadow: 8px 8px 0 #000;
ホバー時: box-shadow: 12px 12px 0 #000;
クリック時: box-shadow: 4px 4px 0 #000;
```

> シャドウはアニメーションさせる。ホバーで広がり、クリックで縮む「押し込む」感覚。

### スペーシング基本単位

```
0.25rem (4px)  — 微調整
0.5rem  (8px)  — 小さい間隔
1rem    (16px) — 標準
2rem    (32px) — カード内パディング
4rem+   (64px) — セクション間
```

### アニメーション

```typescript
// スプリング設定（基本）
const brutalSpring = {
  type: "spring",
  stiffness: 400,
  damping: 15,
};

// ホバー・タップ
whileHover={{ scale: 1.02, y: -2 }}
whileTap={{ scale: 0.98 }}
```

| 対象 | 動き | タイミング |
|------|------|-----------|
| カード登場 | 下から上へ + 微回転 | 0.35s, spring |
| シャドウ | ホバーで拡大、タップで縮小 | spring |
| アイコン | 回転しながら拡大 | 0.3s, delay: 0.15s |
| テキスト | フェードイン + 左から右 | 0.2s, 順次 |
| 背景図形 | ゆっくり回転（装飾） | 15-20s, 無限ループ |

### コンポーネントの基本パターン

**カード構造:**
```
┌─────────────────────────────┐
│ [LABEL]           [#001] ← 番号バッジ
│                             │
│ ┌─────────────────────────┐ │
│ │       ILLUSTRATION      │ │  ← アクセントカラー背景
│ └─────────────────────────┘ │
│                             │
│ TITLE IN UPPERCASE          │  ← font-weight: 900
│                             │
│ Description text here.      │  ← font-weight: 400
│                             │
│ CLICK FOR NEXT →            │  ← ヒント（アニメーション）
└─────────────────────────────┘
        └───────┘
        ハードシャドウ（オフセット）
```

**ボタン:**
```
┌───────────────┐
│   BUTTON      │  ← 背景白、2px黒ボーダー
└───────────────┘
```
- ホバー: scale 1.05, y -2px
- アクティブ時: 背景を黒に反転

### 禁止事項チェックリスト（新画面追加時に確認）

- [ ] ドロップシャドウ（box-shadow with blur）を使っていないか
- [ ] グラデーション背景を使っていないか
- [ ] 薄いグレー（opacity < 0.5）の文字を使っていないか
- [ ] 角丸（border-radius > 0）をカードやボタンに使っていないか
- [ ] アニメーションなしでインタラクティブ要素を作っていないか

### 新しい画面を作るとき

1. 同じカラールールを守る（モノクロ基調 + 1アクセント）
2. ハードシャドウを使う（blur禁止）
3. 登場アニメーションを付ける（spring推奨）
4. ホバー/タップ反応を付ける（インタラクティブ要素すべて）

## B. パターン・ランゲージの理論

> 元ソース: `パターンとは.md`

### パターンの基本構造

| 要素名 | 英語名 | UI表示 |
|--------|--------|--------|
| 番号 | Number | バッジで表示 |
| パターン名 | Name | 最も大きく表示 |
| 導入文 | Intro | 副題として表示 |
| イラスト | Illustration | **視覚的アンカー**（視線の中心） |
| 状況 | Context | 「▼その状況において」 |
| 問題 | Problem | 「しかし〜」 |
| 解決 | Solution | **「▼そこで」**（強調表示） |
| 結果 | Consequence | 「▼その結果」 |

### テキストフォーマット

```
▼ その状況において
（状況の説明）

しかし〜
（問題の説明）

▼ そこで
（解決策の説明）← 最重要

▼ その結果
（期待される結果）
```

### 2つの言語形態の違い

| 比較項目 | 楽天主義実践パターン | 燕市まちづくりパターン |
|---------|-------------------|--------------------|
| 形態 | 見開き2ページの本 | 1枚のカード |
| 情報量 | 豊富（詳細な説明） | 凝縮（要点のみ） |
| 読み方 | 番号順に読み進める「物語的」体験 | 手に取って眺める「カジュアル」体験 |
| 適用場面 | じっくり学ぶワークショップ | 対話ツール・アイスブレイク |

### 重要な設計原則

- **イラストは単なる装飾ではない** — テキストを読む前に概念を直感的に理解させる視覚的アンカー
- カード表示時：イラストを最も目立たせる
- 詳細表示時：テキストより先にイラストが目に入る配置

### JSONデータ形式

```typescript
// 必須フィールド
{
  id: number,           // 1〜N（Language内の連番）
  pattern_name: string, // パターン名
  context: string,      // 「▼その状況において」
  problem: string,      // 「しかし〜」
  solution: string,     // 「▼そこで」（最重要）
}

// 任意フィールド
{
  intro?: string,       // 一言の導入文
  consequence?: string, // 「▼その結果」
  tags?: string[]       // タグ（将来のフィルタ機能用）
}
```

## C. UX設計方針

> 元ソース: `企画書.md` § 4

### ホーム画面

| 原則 | 説明 |
|------|------|
| **ファーストビュー優先** | スクロールなしでメイン機能へアクセス可能に |
| **プレミアム感** | 安っぽくない、信頼できるWebサイトの印象 |
| **優先度の明確化** | Pattern View > Language View > 占い > About |

### Pattern View

| 原則 | 説明 |
|------|------|
| **体験重視** | 機能より「すげー」という感動が先。入った瞬間に圧倒される体験を目指す |
| **3モード切替** | 用途に応じて表示を変更可能（localStorage で保存） |
| **動きの演出** | 静止画面より、常に動いている状態が理想 |

### レスポンシブ

| 原則 | 説明 |
|------|------|
| **PC余白の活用** | maxWidth 900px で広く使う |
| **スマホ最適化** | 縦並びレイアウト、タップしやすいサイズ |

## E. 新しいLanguageを追加する手順

1. `assets/{language_id}_patterns.json` を作成（JSONスキーマは §B 参照）
2. `assets/illustrations/{language_id}/` にイラスト配置（命名: `{番号}_{パターン名}.png`）
3. `src/data/languages.ts` に言語メタデータを追加
4. `git push` → Vercel 自動デプロイ
